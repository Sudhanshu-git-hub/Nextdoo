## Scope decisions

No new search backend, universal tags, notification provider or reminder entity type. Shared tags cover Tasks and Notes only; Goal identifiers/categories, Tracker statuses and Knowledge property options keep their existing meanings. Calendar search covers saved native/imported events and owned Google mirrors; no live provider fetch. Native Knowledge relations cover one-off native events only; imported snapshots/provider relations retain their existing lifecycle boundaries. Relationships remain online commands; task offline behavior is preserved. This narrow additive Calendar FK migration is required to retain referential integrity, with historical migrations unchanged.

The audit is complete before implementation. Delivery will record actual completed/partial requirements and full validation; no test results for new code are claimed here.


## Implemented boundary

- The visible Commands button and `?` outside editable controls open a native modal dialog. Tab/arrow navigation, Enter, Escape, focus return, and mobile layout use the same real destinations. Create a task opens existing Inbox capture; Start Focus opens the existing task-aware Focus screen. The palette never starts a timer without selecting work. Search uses the existing authenticated connected projection, returns at most eight previews and links to the full paginated search. Connectivity failures are explicit.
- Shared search now includes active projects, their sections (shown as project lists), native/imported Calendar events and saved mirrors from active owned Google connections. It retains literal substring matching, stable order, bounded pagination and excludes archived/deleted sources. Hidden Calendar sources remain discoverable by explicit search; Today/Home keep respecting visibility. There is no live provider fetch. Project/list links open the existing task browser with owned filters; the additive sectionId task-query filter is included in its cursor fingerprint, preserving old fingerprints when absent.
- Tasks can select existing active Goals/Milestones/Trackers and confirm links using each original versioned endpoint. Direct links can be removed; inherited Goal paths are labeled and removed via their Milestone. Conflicts retain the selection and require explicit reload. Knowledge linking remains the existing note/record workflow. The task editor links directly to its existing reminder page.
- Tasks and Notes share existing tag IDs and normalization. Shared Search filters those two types through their existing tag tables, and Note tags navigate to that filter. No tag rows are copied and no new taxonomy is introduced. Goal identifiers/categories, Tracker statuses and Knowledge select options retain domain-specific meaning.
- Exact Calendar event pages reuse saved event data and the existing editor. Home/Today, Search and Knowledge references open the original event. Native one-off events can attach existing Notes/Records through Knowledge references; unlinking remains at the source Note/Record. Imported snapshots can be searched/opened but cannot receive new native-event relations. Existing Google Knowledge references remain supported. Dates/Tracker activity continue to use the existing Calendar overlays.

## Integrity and rollout

Apply additive migration `0031_native_calendar_knowledge.sql` before deploying the new application. Historical migrations are unchanged. It adds one nullable typed target and a workspace-composite FK to the existing Knowledge relation table, extends the exclusive-target/type/identity checks, and preserves existing rows. Archived events remain readable through their owned exact-event endpoint, with read-only editing/reference controls. Soft-deleted/archived native events become unavailable references; new links are rejected, source-side unlink stays available, and permanent deletion cascades only the relation. Note/record versions, transaction locks, idempotency, audit/outbox/sync writers remain authoritative. Existing account export serializes the extended relation rows; existing account purge cascades them.

All new relation commands require connectivity. This does not extend the task-only offline command protocol. The event-detail API now supplies the existing CenterEvent read shape for owned native/imported events and active provider mirrors; native mutation contracts and source-version checks are unchanged.

## Partial, deferred and external requirements

No standalone personal List entity exists: search lists are existing project sections. Record property values are searched as before; attachments, file contents, reminder histories and future generated schedules are not global-search types. Search has no ranking/fuzzy/full-document backend and offset pages can move during concurrent edits. Calendar imported/provider events retain their own editing limits. Native event relations currently connect Knowledge notes/records only, not arbitrary Goals/Trackers/Tasks. No recurring native events or native reminders are added.

Reminders remain attached to Tasks and use existing preferences, schedules, cancellation, in-app history and configured email/browser-push delivery. Tracker monthly report delivery remains its separate established contract. No general Goal/Knowledge/Calendar reminder category or new delivery provider is claimed. Real external delivery still requires deployment/provider evidence. Existing Calendar providers, Home card settings and Focus/offline semantics are preserved.

AI, collaboration, native clients, billing, plugins, advanced views and subsequent milestones remain out of scope.
